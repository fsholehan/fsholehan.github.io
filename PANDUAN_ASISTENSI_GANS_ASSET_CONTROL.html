BAB 1: GAMBARAN BESAR APLIKASI (BIG PICTURE)

1.1 Program Apa Sebenarnya Ini?

Aplikasi ini bernama GANS Asset Control, yaitu program pencatat kekayaan dan barang inventaris (aset tetap) untuk bisnis kuliner Gan’s Cafe & Burjo.

1.2 Masalah Nyata Apa yang Diselesaikan?

  1. Rencana Belanja Tercampur Barang Nyata: Daftar barang yang baru sebatas rencana mau dibeli sering tercatat sebagai aset asli, sehingga nilai kekayaan kafe jadi palsu.
  2. Barang Hilang atau Rusak Tanpa Jejak: Tidak ada yang tahu siapa penanggung jawab barang atau kapan terakhir diservis.
  3. Penyusutan Nilai Tidak Dihitung: Mesin kopi 15 juta setelah dipakai 2 tahun tentu nilainya turun (aus). Jika tidak dihitung, laporan laba-rugi kafe jadi tidak akurat.

Solusi Aplikasi: Memisahkan jalur rencana belanja vs aset fisik, mewajibkan persetujuan (verifikasi) sebelum barang diakui, membuatkan label QR Code siap cetak, serta menghitung penyusutan harga dan jurnal akuntansi otomatis tiap bulan.

1.3 Alur Kerja Utama Sistem

  1. Login Pengguna: Masuk sesuai peran akun (Owner, Admin, atau Akuntan).
  2. Input Barang: Staf memasukkan data lewat formulir Input Cepat. Data masuk dengan status Draft atau Menunggu Pemeriksaan.
  3. Verifikasi: Owner atau Akuntan meninjau dan menyetujui barang menjadi status Aktif.
  4. Cetak QR Code: Barcode kotak ditempelkan pada fisik mesin atau perabotan kafe.
  5. Penyusutan & Jurnal: Di akhir bulan, Akuntan menjalankan modul penyusutan bulanan untuk mencatat biaya ke buku besar secara otomatis.

BAB 4: BEDAH KODING MENDALAM FILE-FILE KUNCI

4.1 Bedah File: assets/permissions.py Analogi: Satpam Pintu Masuk VIP

File ini bertugas menghentikan orang yang tidak punya wewenang agar tidak sembarangan masuk ke halaman rahasia (misalnya staf kasir dilarang menyetujui jurnal keuangan).

from functools import wraps
from django.contrib.auth.decorators import login_required
from django.core.exceptions import PermissionDenied


def role_required(*roles):
    def decorate(view_func):
        @wraps(view_func)
        @login_required
        def wrapped(request, *args, **kwargs):
            user = request.user
            if user.is_superuser or user.role in roles:
                return view_func(request, *args, **kwargs)
            raise PermissionDenied

        return wrapped

    return decorate


def is_owner(user):
    return user.is_authenticated and (user.is_superuser or user.role == "owner")

Penjelasan Logika Koding:

  • def role_required(*roles): Ini disebut Decorator (pembungkus pelindung). Tanda bintang *roles membuat kita fleksibel memasukkan beberapa jabatan sekaligus, contoh: @role_required("admin", "owner").
  • @login_required: Pemeriksaan tahap 1. Satpam memastikan pengunjung sudah punya akun dan berhasil login. Kalau belum, langsung diarahkan ke form login.
  • user = request.user: Mengambil data kartu identitas orang yang sedang membuka layar web.
  • if user.is_superuser or user.role in roles: Satpam memeriksa kartu: apakah dia programmer utama (superuser) ATAU jabatannya ada di dalam daftar izin? Jika YA, pintu dibuka (return view_func(...)).
  • raise PermissionDenied: Jika TIDAK, satpam langsung mengusir dan menolak akses dengan melempar Error HTTP 403 (Dilarang Masuk).
Cara Jawab ke Dosen: "Di file permissions.py ini kami membuat decorator mandiri role_required Pak/Bu, agar manajemen hak akses (Role-Based Access Control) terpusat rapi dan mudah ditempelkan di halaman mana saja."

4.2 Bedah File: assets/urls.py Analogi: Papan Petunjuk Jalan / Daftar Menu

File ini menghubungkan alamat link yang diketik orang di browser dengan fungsi koki pemrosesnya di views.py.

from django.urls import path
from . import views

urlpatterns = [
    path("", views.dashboard, name="dashboard"),
    path("aset/", views.asset_list, name="asset_list"),
    path("aset/input-cepat/", views.asset_quick_create, name="asset_quick_create"),
    path("aset/verifikasi/", views.asset_verification, name="asset_verification"),
    path("aset/<int:pk>/", views.asset_detail, name="asset_detail"),
    path("aset/<int:pk>/qr/", views.asset_qr, name="asset_qr"),
    path("penyusutan/", views.depreciation_list, name="depreciation_list"),
]

Penjelasan Logika Koding:

  • path("", views.dashboard, name="dashboard"): Bagian kutip kosong "" artinya alamat beranda/utama (misal http://127.0.0.1:8000/). Saat dibuka, panggil koki views.dashboard.
  • name="dashboard": Nama panggilan rahasia di dalam kodingan. Jika sewaktu-waktu link web diubah, seluruh tombol di file HTML tidak akan rusak karena tombol memanggil namanya, bukan link mentahnya.
  • path("aset/<int:pk>/qr/", views.asset_qr, ...): Perhatikan tanda <int:pk>! Ini adalah parameter dinamis. int artinya harus angka bulat, dan pk adalah singkatan dari Primary Key (Nomor ID unik aset). Jika membuka link aset/15/qr/, sistem tahu bahwa yang diminta adalah QR Code untuk barang nomor 15!
Cara Jawab ke Dosen: "urls.py berfungsi sebagai router atau dispatcher Pak/Bu. Kami menggunakan path converter seperti <int:pk> untuk menangani rute dinamis berdasarkan ID data aset di database."

4.3 Bedah File: assets/views.py Analogi: Koki Utama di Dapur Restoran

File ini memproses logika bisnis: membaca data dari lemari database, memvalidasi input formulir, dan membuat keputusan.

@role_required("admin", "owner")
@transaction.atomic
def asset_quick_create(request):
    if request.method == "POST":
        form = QuickAssetForm(request.POST)
        if form.is_valid():
            data = form.cleaned_data
            asset = Asset.objects.create(
                asset_code=next_asset_code(data["location"]),
                name=data["name"],
                category=data["category"],
                location=data["location"],
                status=Asset.Status.PENDING_REVIEW,
                acquisition_date=data["acquisition_date"],
                acquisition_cost=data["acquisition_cost"],
                residual_value=data["category"].default_residual_value,
                useful_life_months=data["category"].default_useful_life_months,
                created_by=request.user,
            )
            record_audit(request.user, "asset", asset.pk, "quick_created_pending_review")
            messages.success(request, f"{asset.name} dikirim ke antrean verifikasi.")
            return redirect("asset_verification")
    else:
        form = QuickAssetForm()
    return render(request, "assets/quick_asset_form.html", {"form": form})

Penjelasan Logika Koding:

  • @role_required("admin", "owner"): Memanggil satpam dari file permissions tadi! Hanya Admin dan Owner yang boleh mencatat barang.
  • @transaction.atomic: Prinsip "Semua atau Batal Total". Jika terjadi error sistem di tengah jalan, seluruh penyimpanan dibatalkan agar database tidak menyimpan data cacat.
  • if request.method == "POST": Membedakan aksi: jika staf baru membuka halaman kosong itu adalah GET (tampilkan blangko kosong), jika staf sudah menekan tombol simpan itu adalah POST (mulai simpan data).
  • asset_code=next_asset_code(data["location"]): Membuat kode barang otomatis sesuai lokasi (misal lokasi Bar menghasilkan BAR-0001).
  • status=Asset.Status.PENDING_REVIEW: Kunci integritas akuntansi! Barang tidak langsung diakui sebagai aset aktif, melainkan menunggu verifikasi.
  • record_audit(...): Mencatat riwayat digital di buku audit trail: siapa yang menginput dan jam berapa.
Cara Jawab ke Dosen: "views.py adalah controller logika bisnis. Fungsi ini memisahkan alur request GET untuk menampilkan form dan POST untuk memvalidasi isian serta merekam log audit sebelum data disimpan."

4.4 Bedah File: assets/utils.py Analogi: Kotak Perkakas / Kamus Terjemahan

File ini berisi fungsi-fungsi pembantu kecil yang berdiri sendiri dan sering dipakai berulang-ulang di berbagai tempat.

INDONESIAN_MONTHS = (
    "Januari", "Februari", "Maret", "April", "Mei", "Juni",
    "Juli", "Agustus", "September", "Oktober", "November", "Desember",
)

INDONESIAN_SHORT_MONTHS = (
    "Jan", "Feb", "Mar", "Apr", "Mei", "Jun",
    "Jul", "Agu", "Sep", "Okt", "Nov", "Des",
)


def format_indonesian_month(value, abbreviated=False):
    months = INDONESIAN_SHORT_MONTHS if abbreviated else INDONESIAN_MONTHS
    return f"{months[value.month - 1]} {value.year}"

Penjelasan Logika Koding:

  • INDONESIAN_MONTHS = (...): Daftar baku nama 12 bulan dalam bahasa Indonesia.
  • def format_indonesian_month(...): Menerjemahkan tanggal sistem komputer menjadi teks ramah manusia.
  • months[value.month - 1]: Komputer menyimpan bulan dalam angka 1 sampai 12 (misal bulan 3 untuk Maret). Namun dalam koding, urutan daftar selalu dimulai dari angka 0, bukan 1. Maka: 3 - 1 = 2. Item urutan ke-2 adalah "Maret".
  • return f"{months[...]} {value.year}": Menghasilkan format tulisan rapi, contoh: "Maret 2026", yang digunakan pada laporan penyusutan bulanan.
Cara Jawab ke Dosen: "utils.py adalah modular helper functions. Kami memisahkan logika pemformatan nama bulan Indonesia ke sini agar kode di views dan models tetap bersih sesuai prinsip DRY (Don't Repeat Yourself)."

BAB 5: SIMULASI PERTANYAAN DOSEN & JAWABAN SIAP PAKAI

Dosen: "Bagaimana cara sistem kamu mengamankan halaman web agar staf biasa tidak membuka menu rahasia?"
Jawaban Siap Pakai: "Izin menjawab Pak/Bu. Kami membuat modul keamanan khusus di file permissions.py bernama role_required. Fungsi ini bekerja sebagai dekorator pelindung. Ketika sebuah halaman didekorasi dengan @role_required('owner', 'accountant'), sistem akan memeriksa identitas pengguna saat itu. Jika perannya tidak cocok, sistem langsung memblokir akses dan mengeluarkan exception PermissionDenied (HTTP 403 Forbidden)."
Dosen: "Di file urls.py ada sintaks seperti <int:pk>. Apa artinya itu dan apa fungsinya?"
Jawaban Siap Pakai: "Izin menjawab Pak/Bu. <int:pk> adalah URL Path Converter dinamis. int artinya parameter harus berupa angka bulat, dan pk adalah singkatan dari Primary Key (ID unik data di database). Fungsinya agar satu rute URL bisa menangani data spesifik secara fleksibel. Misalnya jika membuka /aset/5/qr/, sistem otomatis tahu bahwa koki di views.py harus membuatkan gambar QR Code untuk barang yang ID-nya nomor 5."
Dosen: "Apa perbedaan peran antara file views.py dan utils.py?"
Jawaban Siap Pakai: "Izin menjawab Pak/Bu. views.py adalah pengendali utama alur bisnis aplikasi: ia menerima permintaan HTTP dari pengguna, memvalidasi formulir, memanggil database, dan menentukan halaman HTML mana yang dirender. Sedangkan utils.py adalah kumpulan fungsi pembantu kecil yang independen dan sering dipakai berulang-ulang, contohnya fungsi pemformat nama bulan Indonesia agar teks laporan seragam."
Dosen: "Kenapa proyek ini perlu ada file tests.py? Apakah tidak cukup dites manual dengan diklik di browser?"
Jawaban Siap Pakai: "Izin menjawab Pak/Bu. Tes manual dengan klik di browser rawan terlewat (human error) dan memakan waktu lama setiap kali ada perubahan kode. File tests.py berisi Unit Test otomatis menggunakan framework pengujian bawaan Django. Cukup ketik perintah python manage.py test assets, komputer akan mengeksekusi puluhan skenario uji—seperti validasi impor Excel, jurnal berimbang, dan rumus penyusutan—hanya dalam hitungan detik untuk membuktikan bahwa tidak ada fungsi yang rusak."
Dosen: "Kenapa data Rencana Pengadaan (Procurement Plan) dan Aset Aktif harus dipisah di tabel berbeda?"
Jawaban Siap Pakai: "Izin menjawab Pak/Bu. Untuk menjaga integritas prinsip akuntansi. Barang di rencana pengadaan sifatnya baru estimasi niat belanja, belum tentu dibeli. Jika langsung dicatat sebagai aset aktif, nilai kekayaan kafe di laporan neraca akan menggembung tidak sah (overstated). Maka di sistem ini harus diverifikasi dulu sampai barangnya fisik ada, baru statusnya diubah menjadi aktif."
Dosen: "Mengapa kamu memakai on_delete=models.PROTECT, bukan CASCADE?"
Jawaban Siap Pakai: "Izin menjawab Pak/Bu. Jika menggunakan CASCADE, seandainya ada staf yang tidak sengaja menghapus nama Kategori atau Lokasi, maka seluruh data barang bernilai jutaan rupiah di bawahnya akan ikut terhapus otomatis beserta riwayat jurnalnya. Dengan PROTECT, database mengunci data tersebut sehingga tidak bisa dihapus selama masih ada barang yang menempel."
Dosen: "Apa fungsi @transaction.atomic pada proses penyusutan dan jurnal?"
Jawaban Siap Pakai: "Izin menjawab Pak/Bu. Dalam akuntansi, pencatatan Debet dan Kredit harus mutlak berimbang. @transaction.atomic memastikan sifat 'all-or-nothing'. Jika terjadi gangguan koneksi atau server mati saat mencatat sisi kredit, sistem otomatis membatalkan (rollback) sisi debet. Sehingga tidak akan pernah ada jurnal yang pincang atau data korup di database."
