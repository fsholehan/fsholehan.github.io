BAB 1: GAMBARAN BESAR APLIKASI (BIG PICTURE)

1.1 Program Apa Sebenarnya Ini?

Aplikasi ini bernama GANS Asset Control, yaitu program pencatat kekayaan dan barang inventaris (aset tetap) untuk bisnis kuliner Gan’s Cafe & Burjo.

1.2 Masalah Nyata Apa yang Diselesaikan?

Di kafe dan tempat makan, banyak sekali barang mahal: mesin espresso, kulkas, blender komersial, meja kursi, kompor, dan AC. Masalah yang sering terjadi:

  1. Rencana Belanja Tercampur Barang Nyata: Daftar barang yang baru sebatas niat mau dibeli sering tercatat sebagai aset asli, sehingga nilai kekayaan kafe jadi palsu.
  2. Barang Hilang atau Rusak Tanpa Catatan: Tidak ada yang tahu siapa penanggung jawab barang atau kapan terakhir diservis.
  3. Penyusutan Nilai Tidak Dihitung: Mesin kopi 15 juta setelah dipakai 2 tahun tentu nilainya turun (mengalami penyusutan). Jika tidak dihitung, laporan laba-rugi bisnis jadi kacau.

Solusi Aplikasi Ini: Memisahkan jalur rencana belanja vs aset fisik, mewajibkan persetujuan (verifikasi) sebelum barang diakui, membuatkan label QR Code untuk ditempel di fisik barang, serta menghitung penyusutan harga dan jurnal akuntansi otomatis tiap bulan.

1.3 Alur Kerja Utama Aplikasi

  1. Staf Login: Masuk sesuai peran akun (Owner, Admin, atau Akuntan).
  2. Input Barang: Staf memasukkan data lewat menu Input Cepat atau impor Excel. Data masuk antrean dengan status Draft atau Menunggu Pemeriksaan.
  3. Verifikasi: Owner atau Akuntan memeriksa data. Jika sudah sesuai, status disetujui menjadi Aktif.
  4. Label QR Code: Sistem membuatkan gambar barcode kotak (QR Code) siap cetak untuk ditempel di mesin atau perabotan kafe.
  5. Akhir Bulan: Akuntan menjalankan modul penyusutan bulanan untuk memotong nilai buku secara adil dan membuat jurnal otomatis.
  6. Dashboard & Opname: Pemilik memantau total aset aktif di layar utama serta mengecek kondisi fisik barang berkala (Stock Opname).

BAB 4: BEDAH KODE BAGIAN DEMI BAGIAN (LINE-BY-LINE)

4.1 Pembagian Peran Pengguna (accounts/models.py)

class User(AbstractUser):
    class Role(models.TextChoices):
        OWNER = "owner", "Owner"
        ADMIN = "admin", "Admin"
        ACCOUNTANT = "accountant", "Akuntan"

    role = models.CharField(max_length=20, choices=Role.choices, default=Role.ADMIN)

Bagian ini tugasnya apa? Memberikan kartu tanda pengenal (peran jabatan) untuk setiap orang yang login ke dalam sistem.
Caranya bagaimana? AbstractUser adalah kartu pengenal standar bawaan Django (sudah punya username dan password). Kita tambahkan satu kolom baru bernama role dengan 3 pilihan pasti: Owner, Admin, atau Akuntan. Standarnya (default), pengguna baru dianggap staf Admin biasa.

4.2 Perlindungan Formulir Aset (assets/models.py)

class Asset(models.Model):
    asset_code = models.CharField(max_length=50, unique=True)
    name = models.CharField(max_length=200)
    category = models.ForeignKey(AssetCategory, on_delete=models.PROTECT, related_name="assets")
    location = models.ForeignKey(Location, on_delete=models.PROTECT, related_name="assets")
    acquisition_cost = models.DecimalField(max_digits=16, decimal_places=2, validators=[MinValueValidator(0)])
    status = models.CharField(max_length=20, choices=Status.choices, default=Status.DRAFT)

Bagian ini tugasnya apa? Menjaga agar data barang aman dan tidak bisa dihapus sembarangan secara tidak sengaja.
Caranya bagaimana? Perhatikan perintah on_delete=models.PROTECT. Artinya: jika ada staf yang tidak sengaja ingin menghapus kategori "Peralatan Bar", sistem akan menolak karena masih ada mesin espresso yang terhubung di bawah kategori itu. Selain itu, harga beli dilindungi MinValueValidator(0) agar tidak ada angka minus.

4.3 Filter Angka di Dashboard (assets/views.py)

@login_required
def dashboard(request):
    assets = Asset.objects.all()
    active_assets = assets.filter(status=Asset.Status.ACTIVE)
    total_cost = active_assets.aggregate(total=Sum("acquisition_cost"))["total"] or Decimal("0")
    plan_total = ProcurementPlanLine.objects.aggregate(total=Sum("total_cost"))["total"] or Decimal("0")

Bagian ini tugasnya apa? Menjadi juru hitung ringkasan data saat pengguna pertama kali membuka dashboard utama.
Caranya bagaimana? Baris filter(status=Asset.Status.ACTIVE) memastikan bahwa total nilai kekayaan yang dijumlahkan hanya dari barang yang sudah sah aktif. Nilai rencana pengadaan (plan_total) dihitung di tempat terpisah sehingga tidak tercampur dengan aset riil.

4.4 Pengaman Penyusutan Bulanan (assets/services/depreciation.py)

@transaction.atomic
def create_depreciation_run(period, user):
    period = period.replace(day=1)
    current_month = timezone.localdate().replace(day=1)
    if period > current_month:
        raise ValidationError("Periode penyusutan tidak boleh berada di masa depan.")
    if DepreciationRun.objects.filter(period=period).exists():
        raise ValidationError("Periode ini sudah memiliki proses penyusutan.")

Bagian ini tugasnya apa? Mencegah salah hitung akuntansi yang bisa merusak laporan keuangan bulanan.
Caranya bagaimana? Simbol @transaction.atomic bekerja seperti prinsip "Semua atau Batal Total". Jika sistem sedang memproses 100 barang lalu di tengah jalan terjadi error pada barang ke-40, sistem langsung membatalkan seluruh operasi dari awal agar data tidak pincang. Perintah berikutnya memastikan satu bulan tidak boleh disusutkan 2 kali.

BAB 5: SIMULASI PERTANYAAN DOSEN & JAWABAN SIAP PAKAI

Dosen: "Kenapa data Rencana Pengadaan (Procurement Plan) dan Aset Aktif harus dipisah di tabel berbeda?"
Jawaban Siap Pakai: "Izin menjawab Pak/Bu. Untuk menjaga integritas prinsip akuntansi. Barang di rencana pengadaan sifatnya baru estimasi niat belanja, belum tentu dibeli. Jika langsung dicatat sebagai aset aktif, nilai kekayaan kafe di laporan neraca akan menggembung tidak sah (overstated). Maka di sistem ini harus diverifikasi dulu sampai barangnya fisik ada, baru statusnya diubah menjadi aktif."
Dosen: "Mengapa kamu memakai on_delete=models.PROTECT, bukan CASCADE?"
Jawaban Siap Pakai: "Izin menjawab Pak/Bu. Jika menggunakan CASCADE, seandainya ada staf yang tidak sengaja menghapus nama Kategori atau Lokasi, maka seluruh data barang bernilai jutaan rupiah di bawahnya akan ikut terhapus otomatis beserta riwayat jurnalnya. Dengan PROTECT, database mengunci data tersebut sehingga tidak bisa dihapus selama masih ada barang yang menempel."
Dosen: "Apa fungsi @transaction.atomic pada proses penyusutan dan jurnal?"
Jawaban Siap Pakai: "Izin menjawab Pak/Bu. Dalam akuntansi, pencatatan Debet dan Kredit harus mutlak berimbang. @transaction.atomic memastikan sifat 'all-or-nothing'. Jika terjadi gangguan koneksi atau server mati saat mencatat sisi kredit, sistem otomatis membatalkan (rollback) sisi debet. Sehingga tidak akan pernah ada jurnal yang pincang atau data korup di database."
Dosen: "Bagaimana alur kerja fitur QR Code di aplikasi ini?"
Jawaban Siap Pakai: "Izin menjawab Pak/Bu. Aplikasi menggunakan pustaka Python 'qrcode'. Setiap kali aset disetujui, sistem membaca ID unik dan kode barang, lalu menggambar file gambar QR Code secara langsung. QR Code ini bisa dicetak dan ditempelkan pada fisik barang. Saat staf melakukan stock opname (pemeriksaan fisik), barcode dipindai untuk membuka detail data aset tersebut."
Dosen: "Metode penyusutan apa yang digunakan dan bagaimana perhitungannya?"
Jawaban Siap Pakai: "Metode utamanya adalah Garis Lurus (Straight Line), Pak/Bu. Rumusnya: Nilai Perolehan dikurangi Nilai Residu (sisa), kemudian dibagi Umur Manfaat dalam bulan. Nilai tersebut dipotongkan secara rata setiap bulannya dari nilai buku barang."
Dosen: "Jika aplikasi ini mau di-deploy ke internet untuk umum, apa saja penyesuaiannya?"
Jawaban Siap Pakai: "Ada tiga hal utama Pak/Bu: Pertama, mengganti database SQLite dengan database server seperti PostgreSQL. Kedua, mematikan mode DEBUG (DEBUG = False) dan mengamankan SECRET_KEY. Ketiga, menggunakan web server produksi seperti Gunicorn dan Nginx dengan enkripsi HTTPS."
